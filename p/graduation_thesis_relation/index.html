ORPF 函数

一种无知的伪随机函数（OPRF）是客户端和服务器之间用于计算伪随机函数（PRF）的两方协议，其中 PRF 密钥由服务器持有，函数的输入由客户端提供。客户端除了获得的输出外，不会学习到任何关于 PRF 的信息，而服务器不会学习到客户端的输入或函数输出。本规范依赖于第 3.1 节[RFC9497]中指定的素数阶 OPRF 构造 modeOPRF （ 0x00 ）。

以下OPRF客户端API被用到:

  • Blind(element)
    • 创建并输出 ( blind , blinded_element )，其中包含输入 element 的盲化表示，表示为 blinded_element ，以及用于撤销盲化过程的值，表示为 blind 。这等效于第 3.3.1 节中[RFC9497]中描述的 Blind 函数。

def Finalize(input, blind, evaluatedElement):
    N = G.ScalarInverse(blind) * evaluatedElement
    unblindedElement = G.SerializeElement(N)

    hashInput = I2OSP(len(input), 2) || input ||
                I2OSP(len(unblindedElement), 2) || unblindedElement ||
                "Finalize"
    return Hash(hashInput)

def DeriveKeyPair(seed, info):
    deriveInput = seed || I2OSP(len(info), 2) || info
    counter = 0
    skS = 0
    while skS == 0:
        if counter > 255:
        raise DeriveKeyPairError
        skS = G.HashToScalar(deriveInput || I2OSP(counter, 1),
                            DST = "DeriveKeyPair" || contextString)
        counter = counter + 1
    pkS = G.ScalarMultGen(skS)
    return skS, pkS

最后, 本规范使用了以下共享API和参数:

  • SerializeElement(element):
    • 将输入element映射到固定长度的字节数组
  • DeserializeElement(buf):

KDF 函数 & MAC 消息验证码

密钥派生函数（KDF）是一种函数，它接受一些初始密钥材料作为输入，并使用它来派生一个或多个密码学上安全的密钥。本规范使用一个具有以下 API 和参数的 KDF：

  • Extract(salt, ikm):
    • 从输入密钥材料 ikm 和可选的字节串 salt 中提取一个固定长度为 Nx 字节的伪随机密钥。
  • Expand(prk, info, L):
    • 扩展伪随机密钥 prk ，使用字符串 info ，生成 L 字节的输出密钥材料。
  • Nx :
    • Extract() 函数的输出大小（以字节为单位）。

本规范还使用了一种基于随机密钥的鲁棒消息认证码（MAC）。有关此特性的更多详细信息，请参见第 10.6 节。基于随机密钥的鲁棒 MAC 的 API 和参数如下：

  • MAC(key, msg):
    • 使用输入 msg 的密钥 key 计算消息认证码，生成固定长度的输出 Nm 字节
  • Nm:
    • MAC() 函数的输出大小（以字节为单位）。

CHF 函数 & KSF 函数

本规范使用一种抗碰撞哈希函数，具有以下 API 和参数：

  • Hash(msg):
    • 将输入 msg 应用于加密哈希函数，生成一个固定长度的摘要，大小为 Nh 字节。
  • Nh:
    • Hash() 函数的输出大小（以字节为单位）。

本规范使用一种密钥拉伸函数（KSF），它是一种缓慢且昂贵的加密哈希函数，具有以下 API：

  • Stretch(msg):
    • 对输入 msg 应用一个密钥拉伸函数来拉伸并增强其抵抗离线字典攻击的能力。该函数还需要满足抗碰撞性。

概述

OPAQUE的定义

OPAQUE被定义为三种功能的组合

  • an Oblivious Psedorandom Function(OPRF)
  • a key recovery mechanism
  • an authenticated key exchange (AKE) protocol
  • 它可以被视为一个编译器 可将任何合适的 AKE 转换成 安全的 aPAKE

OPAQUE的流程:注册与认证密钥交换 (registration and authenticated key exchange)

  • 注册阶段, 用户将其密码注册到服务器, 并在服务器上存储用于恢复凭证的信息。恢复这些凭证仅能靠知道客户端密码来完成。
  • 认证密钥交换阶段, 客户端用其密码来恢复这些凭据, 并随后将它们输入到一个AKE协议中。这个阶段有额外的机制来防止主动攻击者与服务器交互以猜测或确认第一阶段注册的客户端。服务器也能利用这种机制来保护客户端免受这种枚举攻击
